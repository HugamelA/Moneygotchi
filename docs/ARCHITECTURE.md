# Архитектура и структура данных

Документ описывает функциональную и компонентную архитектуру прототипа «Манигочи», структуру хранимых данных и правила игровой экономики на уровне, достаточном для обсуждения с экспертами на промежуточном этапе.

## 1. Общие сведения

Прототип представляет собой одномодульное нативное Android-приложение на Kotlin с интерфейсом на Jetpack Compose. Серверная часть отсутствует; приложение полностью работоспособно без подключения к сети. Состояние игры хранится локально в `SharedPreferences`, игровой и учебный контент — в JSON-файлах каталога `assets`.

Архитектурный принцип прототипа — **вынесение контента и параметров баланса из кода**: все числовые параметры экономики, каталог товаров, задания и события задаются в конфигурационных файлах и загружаются при запуске. Это обеспечивает выполнение требования 2.5.14 ТЗ: новое задание или товар добавляется правкой JSON-файла без изменения программной логики.

## 2. Компонентная архитектура

Приложение разделено на четыре слоя.

| Слой | Назначение | Файлы |
|---|---|---|
| Контент | Задания, товары, события, параметры экономики | `assets/tasks.json`, `shop.json`, `events.json`, `economy.json` |
| Загрузка контента | Разбор JSON и предоставление данных остальным слоям | `Economy.kt`, `ShopData.kt`, `TasksData.kt`, `EventData.kt` |
| Состояние и игровая логика | Хранение профиля, расчёт показателей питомца, звёзд, уровней, выбор событий | `AppStorage.kt`, `EventEngine.kt`, `PetData.kt`, `ParentData.kt` |
| Интерфейс | Экраны и навигация | `MainActivity.kt` и файлы `*Screen.kt`, `MainScene.kt`, `MainHud.kt`, `PetMenu.kt`, `TutorialOverlay.kt`, `EventDialog.kt`, `ParentGate.kt` |

Вспомогательные компоненты: `NameDeclension.kt` (склонение имени питомца по падежам для текстов заданий и событий), `PetAssets.kt` (сборка изображения питомца из слоёв окраса и маски), `Zones.kt` (разметка интерактивных зон на фоновых изображениях), `Helpers.kt`, `Components.kt`.

### 2.1. Навигация

Навигация реализована в `AppRoot()` (`MainActivity.kt`) через строковое состояние текущего экрана. Основные экраны:

| Экран | Назначение |
|---|---|
| `welcome` → `pet_setup` → `color_setup` | Первый запуск: выбор вида и имени питомца, выбор окраса |
| `tutorial` | Главный экран с пошаговым обучением |
| `main` | Главный экран-комната: питомец, баланс, день, цель, показатели; интерактивные предметы комнаты ведут в разделы |
| `coins` | Распределение монет по конвертам и копилке (план бюджета) |
| `shop` → `cart` | Магазин и корзина с оплатой из конвертов |
| `piggy`, `goal` | Копилка и финансовая цель |
| `tasks` | Финансовые задания |
| `settings` → `parent` → `dev` | Настройки, раздел для взрослого, служебный экран для демонстрации |
| `telescope`, `console_game` | Бонусные экраны, открываемые после достижения целей |

Главный экран организован как иллюстрированная комната, в которой разделы приложения соответствуют предметам: компьютер — магазин, ящик стола с конвертами — бюджет, банка с монетами — копилка, книжная полка — задания, кровать — завершение игрового дня.

## 3. Игровой цикл

Игровой период — **игровой день**. Он завершается по действию пользователя (нажатие на кровать и подтверждение), а не по календарному времени.

1. Ребёнок получает монеты на баланс (стартовый бюджет, доход за день, награды за задания, события).
2. Распределяет монеты по трём направлениям: конверт «Обязательное» (еда, уход), конверт «Необязательное» (лакомства, игрушки), копилка (накопления на цель).
3. Покупает товары в магазине. Оплата товара возможна только из конверта соответствующей категории; покупка требует подтверждения.
4. Применяет купленные товары к питомцу, изменяя сытость и настроение.
5. Решает задания и реагирует на игровые события.
6. Завершает день. Приложение начисляет доход, звёзды, уменьшает показатели питомца и показывает итог дня с объяснением.

## 4. Структура данных

### 4.1. Профиль и состояние (`SharedPreferences`, файл `my_pet_prefs`)

| Группа | Ключи | Тип | Смысл |
|---|---|---|---|
| Профиль | `pet_created`, `pet_name`, `pet_appearance`, `pet_color` | bool, string, int, int | Наличие питомца, имя, вид (индекс), окрас (индекс) |
| Показатели питомца | `hunger`, `happiness` | int 0–100 | Сытость и настроение |
| Развитие | `stars`, `pet_level` | int | Звёзды к следующему уровню, текущий уровень; стадия вычисляется по уровню |
| Время | `days_with_pet` | int | Номер текущего игрового дня |
| Бюджет | `coins`, `coins_needs`, `coins_wants` | int | Нераспределённый баланс; конверты «Обязательное» и «Необязательное» |
| Накопления и цель | `piggy_balance`, `goal_name`, `goal_price`, `goal_start_day`, `goals_completed`, `completed_goals` | int, string, int, int, int, set | Копилка, текущая цель, день её постановки, история достигнутых целей |
| Покупки | `shop_cart`, `inventory`, `bed_owned` | set «id:кол-во», bool | Корзина, купленные товары, наличие лежанки |
| Задания | `completed_tasks`, `chosen_options`, `tasks_total`, `tasks_correct` | set, set «id=вариант», int, int | Пройденные задания, выбранные ответы, счётчики |
| События | `last_event_day`, `pending_event_id`, `event_last_day_<id>`, `event_count_<id>`, `price_override*` | int, string, int, set | Расписание событий, временные изменения цен |
| Дневные флаги | `budget_spread_today`, `piggy_added_today`, `correct_tasks_today` | bool, bool, int | Действия за текущий день для расчёта звёзд |
| Статистика для взрослого | `stats_hunger_sum`, `stats_happiness_sum`, `stats_days` | int | Суммы для средних показателей |
| Обучение | `tutorial_shown`, `tutorial_active`, `tutorial_step`, `seen_zones` | bool, bool, int, set | Состояние обучения и подсказок |

Сброс профиля (`AppStorage.reset()`) полностью очищает файл настроек и возвращает все показатели в исходное состояние.

### 4.2. Игровая экономика (`economy.json`)

| Раздел | Параметры |
|---|---|
| `start` | Стартовый баланс 40 монет, сытость 80, настроение 80, максимум показателя 100 |
| `day.sleepIncome` | Базовый доход 15; бонус +10 за сытость и +10 за настроение при значении не ниже 50; максимум 35 |
| `day.decay` | Убывание за день: сытость −16, настроение −12 |
| `day.hungerAffectsMood` | Коэффициенты влияния голода на настроение |
| `stars` | Правила начисления звёзд за день (не более 3) |
| `levels` | Пороги уровней, стадии «малыш» (с 1 уровня), «подросток» (с 4), «взрослый» (с 7) |
| `goals` | Три цели: лежанка (80), телескоп (250), приставка (350) |
| `tasksRules` | Награда за задание выдаётся однократно; задания не дают звёзд |

### 4.3. Каталог (`shop.json`)

Категория товара содержит поле `paymentSource` (`needs` или `wants`), которое определяет конверт оплаты. Товар содержит цену, влияние на сытость (`hungerEffect`) и настроение (`happinessEffect`); лакомства привязаны к виду питомца (`petType`). Особые товары (категория `special`) являются финансовыми целями и покупаются из копилки; лежанка даёт постоянный эффект (`perk`): настроение убывает медленнее и растёт быстрее.

### 4.4. Задания (`tasks.json`)

Каждое задание содержит тему (`budget`, `savings`, `payments`), сложность, формируемый навык (`skill`), правильную логику (`logic`), день открытия (`unlockDay`), награду, текст ситуации, подсказку и 2–3 варианта ответа. Вариант ответа содержит оценку (`recommended`, `acceptable`, `less_favorable`), реплику-последствие (`petReply`) и объяснение для ребёнка (`explanation`). Текст ситуации может содержать шаблоны имени питомца в нужном падеже.

### 4.5. События (`events.json`)

Событие — игровая ситуация с выбором (подарок, скидка, непредвиденный расход на лечение, день рождения друга, подработка, находка). Эффекты события ограничены правилами: доход не более 20, расход не более 25 монет, событие не причиняет вреда питомцу. В первые десять дней события идут по фиксированному расписанию (дни 2, 4, 6, 8, 10), далее — раз в три дня случайным образом с учётом весов и интервалов повторения.

## 5. Правила расчёта

**Доход за день:**

```
доход = min(15 + 10·[сытость ≥ 50] + 10·[настроение ≥ 50], 35)
```

Показатели берутся на момент завершения дня, до их убывания.

**Звёзды за день** (по одной за каждое условие, не более 3): питомец сыт (сытость ≥ 50), питомец доволен (настроение ≥ 50), в течение дня в копилку отложено больше нуля монет (включая перенос остатков конвертов в копилку при завершении дня). Звёзды начисляются только за финансовые решения и заботу; задания и мини-игры звёзд не дают. Звёзды не отнимаются.

**Уровень и стадия.** Для перехода на следующий уровень требуется число звёзд по порогам `[0, 2, 5, 9, 14, 20, 27, 35, 44, 54]`, после последнего порога — +20 за уровень. Стадия развития определяется уровнем: 1–3 — малыш, 4–6 — подросток, 7 и выше — взрослый. Тем самым рост питомца зависит от совокупности решений за несколько игровых дней (требование 2.5.10).

**Убывание настроения с учётом голода:**

```
убывание_настроения = 12 · (1 + 0,5 · max(0, 50 − сытость) / 50) · k_лежанки
```

**Рост настроения от товара:**

```
прирост = эффект · (1 − 0,15 · max(0, 50 − сытость) / 50) · k_лежанки
```

где `k_лежанки` = 0,85 для убывания и 1,15 для роста при наличии лежанки, иначе 1.

**Бюджет.** Монету можно положить в конверт только при её наличии на балансе, поэтому сумма распределения не может превысить доступный бюджет. Покупка списывает монеты из соответствующего конверта; при нехватке покупка блокируется, и приложение сообщает, в каком конверте и сколько монет не хватает. Отрицательный баланс невозможен.

## 6. Ограничения текущей архитектуры и план доработки

1. Расчёт итогов дня реализован в обработчике экрана (`MainScreen.kt`). До финала он будет вынесен в отдельный компонент игровой логики без зависимостей от интерфейса, что позволит покрыть его модульными тестами (требование 3.4).
2. Для сравнения плана с фактом будет добавлено хранение плана дня и журнала покупок текущего периода.
3. Имя пакета `com.example.myapplication` будет заменено на уникальное для совместимости с RuStore (требование 3.3).
